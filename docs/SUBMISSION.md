## Inspiration

Every summariser asks you to paste a document into a box and trust it. For a discharge summary, a contract or a payslip that is a real decision — and most tools do not even tell you that a decision was made. Hybrid inference finally makes the honest version possible: the same feature can run locally for private text and in the cloud for text that is not private. We wanted to build the tool that shows its own work.

## What it does

VaultBrief briefs a document in seconds and shows you the privacy cost of doing so.

1. A **local scan** scores the text 0–100 for identifiers, health, finance, credentials and legal terms. Three local layers decide it, none of them a network call: explainable rules with Luhn validation, a **Presidio-derived entity layer** with Korean checksums (resident number, business number, driver licence, passport, account) and context-word confidence, and a **transformers.js embedding signal** that catches paraphrase ("white cell count … two weeks of tablets") no keyword would catch.
2. A **router** turns that score plus the document length and the device's model availability into an `InferenceMode`.
3. The brief is generated by **Firebase AI Logic**: Gemini Nano on-device for private text, a cloud-hosted Gemini for long public text. When the browser has no Nano, the same private route runs on **WebLLM** over WebGPU — a quantised open model, downloaded once, cached. Long private documents are briefed map-reduce style in on-device passes, and transformers.js drops repeated passages before they cost another pass.
4. A **privacy receipt** reports where inference actually happened (from `response.inferenceSource`, aggregated over every pass), how many characters were transmitted, how many stayed local, token counts, how many entities the Presidio layer validated by checksum, the semantic signal, and any fallback.

5. The receipt is **sealed and checkable**: a canonical SHA-256 digest, a SHA-256 fingerprint of the document it was issued for, an ECDSA P-256 signature from a per-browser key carried inside the file, and a `prev`/`seq` chain through the ledger. Press **Verify receipt** in the app, or run `npm run verify:receipt` / `scripts/verify-receipt.mjs` on an exported receipt. Editing a field breaks the digest; a different document breaks the fingerprint; a deleted run breaks the chain.

The rule is about identifiers, not about the score: any document carrying a maskable identifier is masked before **any** cloud call — even a public article with one footer address — and with masking switched off the run is refused. That is the one thing VaultBrief will not do: send identified text to the cloud. When the on-device engine itself fails mid-run, the run stops with an error instead of quietly continuing in the cloud.

## How we used Firebase AI Logic

One `getGenerativeModel()` call site, two very different execution environments:

- `getAI(app, { backend: new GoogleAIBackend(), useLimitedUseAppCheckTokens: true })` — limited-use App Check tokens, because generative models enforce replay protection.
- `getGenerativeModel(ai, { mode, inCloudParams: { model: "gemini-3.5-flash-lite", generationConfig: { responseMimeType: "application/json", responseJsonSchema: BRIEF_SCHEMA } }, onDeviceParams: { createOptions: { expectedInputs: [{ type: "text", languages: ["en"] }], … } } })`
- `model.initializeDeviceModel(progressCallback)` is called inside the button's click handler, because Chrome only downloads or resumes the on-device model with user activation. Both on-device modes are initialised (`PREFER_ON_DEVICE` and `ONLY_ON_DEVICE` are separate model objects in the SDK), and the route is decided on the device state **after** preparation, not before.
- `result.response.inferenceSource` is what the receipt prints, and what the ledger counts. We never assume the mode we asked for is the mode that ran.
- The app maps its own policy to all four modes: `ONLY_ON_DEVICE` for private text (refusing rather than falling back), `PREFER_ON_DEVICE` for short public text, `PREFER_IN_CLOUD` for long public text, and `ONLY_IN_CLOUD` for the masked-copy route.

Other Firebase products: **App Check** (reCAPTCHA Enterprise in production, debug token for review builds), **Remote Config** for the sensitivity threshold and model name, **Firestore + Anonymous Auth** to mirror receipts under the user's own anonymous identity (optional, never blocking).

## How we built it

React + TypeScript + Vite, no backend. The engine is pure TypeScript with a strict boundary: `src/engine/hybrid.ts` is the only module that imports `firebase/ai`; everything else is route-agnostic and unit-tested in Node. An MV3 side panel in `extension/` hands the current tab's text to the app.

Three open-source integrations do the local work: `mlc-ai/web-llm` (WebGPU device engine), `huggingface/transformers.js` (local embeddings: semantic signal, duplicate removal) and `microsoft/presidio` (its recognizer/anonymizer semantics ported to TypeScript; the real package runs as a CI-time oracle over a labelled corpus). Details and the trade-offs we chose: [docs/RESEARCH-OSS.md](RESEARCH-OSS.md).

Firebase Agent Skills (`firebase-ai-logic-basics`) were used for App Check and provider setup guidance, and Chrome's `summary-of-summaries` demo shaped the map-reduce chunking (`measureInputUsage`-style quota awareness, recursive merging).

## Challenges we ran into

- **Two privacy questions, one engine.** A keyword like "diagnosis" should raise the score but must never be rewritten; a card number must be. Our first redaction pass rewrote the word "patient" in the middle of a medical record. Splitting "signal" rules from "value" rules fixed it, and a test now locks it in.
- **Token accounting for a router.** A short private document needs no redaction (it never leaves), a long private one needs chunking, and a sensitive document without a local model needs a masked copy. Modelling "characters that actually crossed the network" instead of "characters processed" made the receipt meaningful.
- **Honest demo mode.** Reviewers will open the app on hardware without Gemini Nano and possibly without our project. The app detects both and says so: a banner, a `simulated` stamp on every receipt, and a device panel that reports `availability` verbatim.

## Accomplishments we are proud of

- A routing engine where the privacy rule is enforced in exactly one place and cannot be bypassed by a policy setting.
- A receipt that is generated from the SDK's own answer rather than from our intent.
- 199 tests (198 offline, one opt-in live model check) including a jsdom run of the entire screen, an SDK contract check that calls `generateContent()` against the real SDK with a fake key and proves the request reaches `firebasevertexai.googleapis.com`, a static MV3 extension check that also proves the side panel and the app agree on their handshake protocol, a WebLLM adapter test against the package's real model catalogue, a Firestore-rules drift test, measured per-keystroke budgets, and a Presidio cross-validation that measures the port against the reference implementation — including the false positives we chose not to reproduce.
- A receipt that a third party can verify with 30 lines of Node and no dependency of ours, plus an in-app verifier that shows each check passing.
- Masking that is measured, not asserted: the receipt states how many entities were validated by a checksum and how many were raised by context words.

## What we learned

Hybrid inference is not "on-device with a fallback". It is a product decision that has to be made in the open: which text may leave, which model answers, and what the user is told afterwards. The SDK gives you the mechanism; the interface has to give the user the receipt.

## Testing instructions for judges

1. Open the live demo in Chrome 139+ desktop (on-device path) or any browser (cloud path).
2. Press **Hospital discharge summary** → the routing console shows a device-only route and the receipt shows 0 characters sent. Without Gemini Nano, press **Download WebLLM model** (WebGPU browsers) and the same route runs on the downloaded model; with neither, the app offers the masked-copy route instead — switch **Mask identifiers before cloud** off and press *Brief this document* to see it refuse.
2b. On any document, the **Presidio entity layer** panel lists what was recognised, which matches a checksum (✓) and which were raised by context words (*ctx*).
3. Press **Public policy newsletter** → the cloud route; the receipt shows the characters that were sent.
4. On a long private document (the NDA) press **Stop** during the map-reduce run: the brief panel reports which pass it stopped after and no receipt is written.
5. After any run, press **Verify receipt** → **Verify**: digest, signature, document fingerprint (and the chain, when there is a previous receipt) pass one by one. Edit one character of `cloudChars` in the JSON and verify again: the digest check fails.
6. `npm test`, `npm run verify:oss`, `npm run verify:extension`, `npm run verify:receipt`, `node scripts/verify-sdk-path.mjs`.
